up

UP

The portal passed the latest check cycle (every 10 seconds by default). DNS resolved and TCP connected to the portal port. Magnum also needs a short HTTP MPEG-TS pull from this VPS (/watch plays from here). Strong 8K does not: a datacentre often gets HTTP 404/challenge on player_api.php while TVs still play. Those cards stay UP with xtream vps-blind. If the VPS can log in to Xtream, the xtream flag is ok.

Use it. A card marked UP is currently working for playback. N passes in a row on a card is how many cycles in a row it has stayed up, and N outages in 24h is how many separate outages that host had in the last day.

down

DOWN

The portal failed the latest check cycle. DNS or TCP failed, or the panel explicitly rejected the host. The red dns / tcp / mpeg-ts (Magnum) or xtream (Strong 8K) flags show which step broke; reason is the specific code (for example dns_nxdomain, tcp_timeout, stream_452, stream_auth). Magnum must yield a real MPEG-TS pull from this VPS because /watch plays from here. Strong 8K is marked down for DNS/TCP failure, panel codes 452/453/456/464 (blocked / DNS-locked), or Xtream JSON that refuses the account. A player_api 404 or Cloudflare challenge from the VPS is not a Strong down — home players often still work. stream_452 is the panel telling every channel to fail (blocked / DNS-locked). A redirect to black.ts is ignored — that placeholder can look “up” while real channels return 452.

Do not use it. Players will not get a working stream from this URL. N fails in a row is how many cycles in a row it has been down. After 3 failures (~30 seconds at a 10s check interval) on a live URL, playlists on that host are swapped to a healthy standby. A down standby is never chosen for failover.

Cloudflare proxy

Cloudflare Proxy

The hostname resolves to a Cloudflare anycast IP (orange-cloud). Every HTTP request — including the MPEG-TS stream — goes through Cloudflare’s reverse proxy, not straight to the origin. Hover the badge on a card to see the nameserver hosts.

This is the more likely block. Cloudflare can 403, challenge, or TOS-disable IPTV while DNS and TCP still look fine. We have already seen that on a proxied host: player_api.php returned HTTP 403 with server: cloudflare. Failover will still use a proxied standby if nothing better is healthy, but only as a last resort after origin hosts and Cloudflare-NS-only hosts. If a live card is still UP, the stream is getting through right now — treat it as fragile, not preferred.

Cloudflare NS

Cloudflare NS

The domain’s nameservers are Cloudflare (eric.ns.cloudflare.com and similar — those first names are real Cloudflare NS hosts), but the A record is not in Cloudflare’s proxy ranges. DNS is at Cloudflare; stream traffic goes to the origin IP (grey-cloud).

Less likely to block the stream itself. Cloudflare is not sitting on the HTTP path, so they cannot WAF the MPEG-TS the way a proxy can. Residual risk: they still control DNS, so they can orange-cloud the hostname later without you changing the URL. Safer than Proxy for playback; still not as clean as a host with no Cloudflare badge.

Frequent failure

Frequent failure

This URL has gone down at least three separate times in the last 24 hours (not just one outage that lasted several check cycles). Failover skips these standbys while any other healthy option exists. They are only used if every non-frequent standby is down.

Treat it as unreliable even if the latest card says UP — it has been flapping. Counts reset as those downs age out of the 24-hour window. On the signal map it is an amber square marked !, and its card shows two amber signal bars.

Signal bars & signal map

Every card carries TV-style signal bars that sum up the last day. Four green bars: up, no outages in 24 hours. Three: up, but it went down once or twice in the last day. Two amber bars: flapping (Frequent failure). One red bar: down right now.

The signal map on the Monitor and Playlists pages shows one square per standby URL, grouped by lane and always in the same order: green is up, amber with ! is flapping, red with ✕ is down. Hover a square for the host and its 24-hour outages; click it to jump to that card.

A

Reliability grades

Every standby gets a grade from the share of the last 30 days on which it had at least one outage, as seen from the VPS, scaled to 30 days: A 0–2 days, B 3–6, C 7–12, D 13–20, F 21 or more. Counting days rather than outages means one bad spike only costs a host one day.

Days when 75% or more of the pool failed at once are treated as VPS-side incidents (a firewall block or network trouble on the VPS) and are not counted against any host — they show as faint bars in the 30-day strips. Hosts that fail together as a group on other days, such as a family of names sharing one panel, still count: from the VPS they really are unreliable.

The Reliability panel lists Best picks — the most reliable healthy hosts in each lane — and Avoid, the worst. Choose URL lists healthy hosts best grade first, with the grade at the start of each option. The History table has a grade column and a Worst grade sort. Grades describe the past; a host's current UP/DOWN state still decides whether it can be used.

switch

Switch / Choose URL

On the Playlists page, Switch picks the best healthy standby (same preference as auto failover: origin, then Cloudflare NS, then Cloudflare proxy; frequent-failure standbys are skipped while anything else is up). Magnum playlists only list Magnum-tagged URLs; Strong 8K only lists Strong 8K. Switch stays on the current lane (public or VPN). Choose URL opens a dropdown of that pool so you can pick a specific host, including a Strong 8K VPN host when the player is on a VPN. Down URLs are listed but cannot be selected. Immediately before EPGenius runs, that host is probed again (DNS, TCP, and MPEG-TS). Auto-failover and Switch try the next ranked standby if it fails; Choose URL aborts and leaves you on the current DNS. After either action, Switch back can return to the original DNS if that host is still healthy. Magnum auto-failover uses the same EPGenius call as Strong 8K.

90 days

History

The History tab keeps each URL’s separate outages for 90 days — every time it went from up to down, with the fail reason. Use 90-day / 7-day / 24-hour counts to judge which hosts are historically stronger, not just which ones are up this cycle.

This is not the same as Frequent failure. That badge still only looks at the last 24 hours so failover does not blacklist almost every host. History is for comparing URLs over a longer window. Counts start from when this store was created; older days fill in as time passes.

watch

Watch

/watch is a Chromium web player for friends. It uses a dedicated Xtream account (up to 5 streams at once). Magnum playlist failover updates Watch’s portal DNS so live TV and Movies/Shows follow the new Magnum host. Sign-in is a site login you hand out — the panel username and password never appear in the browser. Chrome or Edge recommended.

Strong 8K VPN

Strong 8K VPN DNS

Strong 8K now rejects VPN clients on the normal public DNS hosts. The vpn: list in urls.yaml is a separate allowlist of hosts that work when the player is on a VPN. Those cards have a blue badge and their own tab. Health checks use the VPS public NIC.

Auto failover never picks a VPN host, and it will not move a playlist that is already on a VPN host onto a public host. A device off VPN cannot use a VPN DNS, and a device on VPN cannot use a public Strong 8K DNS. Use Choose URL when you deliberately want to match the player’s VPN state.
